# 硬件兼容性

本页记录 PXEOS 的内核、驱动、平台与三架构构建边界。FOG 官方提交和同步状态见[上游同步](上游同步.md#fog-上游同步记录)；业务协议和 disk permit 见[RootPXE 集成](RootPXE集成.md)，运行失败与联调清单见[故障处理](故障处理.md)。

## 指定能力状态

Linux 6.18.38 默认版本、三套 Buildroot headers、ARM64 gzip initramfs/平台支持、x86/x64/arm64 `CONFIG_R8169=y` 和 PCIe ASPM `DEFAULT` 的状态为“指定能力已同步，完整 Kconfig/构建/真机待验证”。三份 kernel config 尚未实际对 Linux 6.18.38 运行 `olddefconfig`，也未全量对齐 FOG regenerated config。

QEMU 可用于受控的引导、initramfs 解压和协议路径检查；它不能替代真实 ARM64 硬件，也无法模拟真实 Realtek NIC 行为。

## Realtek 驱动迁移

内核升级与网卡驱动迁移是两个独立动作。驱动迁移在 x86、x64、arm64 三套内核配置统一启用 `CONFIG_R8169=y`，并仅在配置层禁用厂商 `R8125`、`R8126`、`R8127`、`R8168`。

厂商源码、Kconfig、Makefile 及四个驱动目录仍保留：这既保持 FOG 补丁基线，也使同批次回退可恢复相符的配置、驱动选择和产物；这些厂商驱动不会编入当前内核。RTL8125、RTL8126、RTL8168 由内核 `r8169` 接管；RTL8127 为 10GbE，当前运行时不支持。

PCIe ASPM 使用内核 `DEFAULT` 策略，不强制 `performance` 或 `powersave`。

## 构建与回退边界

| 架构 | 内核产物 | initramfs 产物 |
|---|---|---|
| x64 | `bzImage` | `init.xz` |
| x86 | `bzImage32` | `init_32.xz` |
| arm64 | `arm_Image` | `arm_init.cpio.gz` |

内核或驱动配置改动必须重建对应架构的同批次产物。发布或回退必须同时恢复同批次配置、驱动选择（含保留的厂商源码树）以及上表中的内核和 initramfs；不得只替换单个内核或 initramfs。

当前尚未完成三架构构建，或在可牺牲真实磁盘上完成 BIOS/UEFI、512e/4Kn、NVMe、NFS/SMB、网络、存储、PXE、休眠/唤醒、LVM、`attention` 与重试链路验收。必须在实际 RTL8125/RTL8126/RTL8168 设备及 ARM64 设备上复核，严禁在开发机系统盘验证。
