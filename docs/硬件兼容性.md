## USB 启动显示

- USB 镜像脚本为部署/捕获、完整注册、快速注册、兼容信息与调试这五个 PXEOS GRUB 条目分别设置显示模式，并在 Linux 命令行统一传入控制台字体参数。Memtest 和 BIOS/EFI iPXE 跳转条目不继承这些设置。

```text
# USB 镜像脚本
create-usb-image.sh
# 五个 PXEOS GRUB 条目的显示模式
gfxpayload=1024x768,auto
# Linux 命令行的控制台字体参数
fbcon=font:VGA8x16
```

- 修改 USB 显示策略后只需重新执行该脚本生成新的 USB 镜像；无需为此单独重编 PXEOS 内核或 initramfs。实际显示模式仍取决于目标固件、显卡和显示器是否接受 1024×768，必须在代表性的 BIOS 与 UEFI 硬件上复核。

## Realtek 驱动迁移

- 内核升级与网卡驱动迁移是两个独立动作。驱动迁移在 x86、x64、arm64 三套内核配置统一启用内核驱动，并仅在配置层禁用四个厂商驱动。

```text
# 三架构统一启用
CONFIG_R8169=y
# 仅在配置层禁用的厂商驱动
R8125
R8126
R8127
R8168
```

- 厂商源码、Kconfig、Makefile 及四个驱动目录仍保留：这既保持 FOG 补丁基线，也使同批次回退可恢复相符的配置、驱动选择和产物；这些厂商驱动不会编入当前内核。RTL8125、RTL8126、RTL8168 由内核 r8169 接管；RTL8127 为 10GbE，当前运行时不支持。
- PCIe ASPM 使用内核默认策略，不强制性能或省电策略。

```text
DEFAULT     # 当前策略
performance # 不强制启用
powersave   # 不强制启用
```

## 构建与回退边界

- 三架构分别使用以下内核和 initramfs 产物。

```text
# x64：内核与 initramfs
bzImage
init.xz
# x86：内核与 initramfs
bzImage32
init_32.xz
# arm64：内核与 initramfs
arm_Image
arm_init.cpio.gz
```

- 内核或驱动配置改动必须重建对应架构的同批次产物。发布或回退必须同时恢复同批次配置、驱动选择（含保留的厂商源码树）以及上述内核和 initramfs；不得只替换单个内核或 initramfs。
- 当前尚未完成三架构构建，或在可牺牲真实磁盘上完成 BIOS/UEFI、512e/4Kn、NVMe、NFS/SMB、网络、存储、PXE、休眠/唤醒、LVM、attention 与重试链路验收。必须在实际 RTL8125/RTL8126/RTL8168 设备及 ARM64 设备上复核，严禁在开发机系统盘验证。
