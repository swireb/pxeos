## 安全配置

## 默认 Root 凭据

- 三种 filesystem 配置（x64、x86、arm64）均启用了 Root 密码登录；默认账号与密码如下。修改配置后必须重新构建对应架构的 initramfs 才会生效。

```text
# 公开的默认账号与默认密码
root
pxeos
# x64 initramfs
init.xz
# x86 initramfs
init_32.xz
# arm64 initramfs
arm_init.cpio.gz
```

- 该密码为所有设备共享的弱默认密码，不应视为加密或安全保护。仅应在隔离的管理网络中使用；在发布或接入生产网络前，必须修改默认密码。

## 敏感信息与运行时边界

- 网络诊断和任务错误输出必须过滤 token、SMB 密码和凭据文件路径；日志不得输出完整凭据。PXEOS 不直接复制 FOG 运行时脚本或服务端 endpoint，仍使用 RootPXE 的 token、MAC、任务快照与 attention 协议。

## HTTP 引导与 HTTPS 控制通信

- iPXE 的内核与 initramfs 引导可继续使用 HTTP；PXEOS 启动后保留服务端下发的完整控制 URL，不固化主机名或端口，也不会自行从 HTTPS 降级或回退到 HTTP。RootPXE 控制 URL 为 HTTPS 时，checkin、磁盘许可、进度、阶段、完成、错误重试、初始化和手动多播控制请求使用下列 curl 选项；HTTP URL 则保持原有兼容行为。

```text
# 服务端下发完整控制 URL 的字段
web
pxeapi
# HTTPS 控制请求使用的 curl 形式
curl -k
```

- 该选项保留 TLS 加密，但不验证证书链、SAN 或服务器身份，存在受控网络内的中间人风险。该例外仅限 PXEOS 到 RootPXE 的控制通信，不得扩展到镜像源、第三方下载或 SSH；token、密码和其他凭据仍不得记录到日志。
- 与 RootPXE 的磁盘许可、主机名和离线镜像写入边界见[RootPXE 集成](RootPXE集成.md)，失败后的 attention 与重试处理见[故障处理](故障处理.md)。

## 存储进程与恢复身份

- 新版NFS/SMB任务要求存储协议v1、helper、numericIdentity、durablePublish及有效Linux boot_id能力；缺失时拒绝，不用root直接NAS访问兼容旧端。NFS使用显式配置的UID/GID（0..4294967294）及AUTH_SYS，无Kerberos；NAS的squash、ACL与白名单仍决定授权，客户端数值身份不是强认证。
- 普通helper在任何NAS open前完成辅助组、GID、UID、能力清理和NoNewPrivs；降权后设置父死亡信号并复核父进程。挂载使用单独固定NFS入口，只保留CAP_SYS_ADMIN及配置身份；块设备仍root，所有NAS数据经本地有界管道。helper不接受任意shell或raw block FD，不通过NFS uid/gid挂载选项改变身份。
- FD3私有本地上下文由root所有、权限0600，绑定原owner/nonce/配置修订/版本/目标；FD4请求/ACK、FD5数据、FD6结果固定。SMB密码仅在认证响应和0600临时凭据文件中使用，不放helper上下文、命令行、日志、状态或恢复副本。
- SMB挂载后核验kernel实际方言和非guest会话，仅2.1/3.0/3.0.2/3.1.1；NFS固定版本不回退，auto仅明确版本拒绝可继续。认证/路径/权限/网络失败不得成为降级理由。原执行和恢复固定已核验实际版本，不重新auto。
- 五存储回调只接受原token/MAC/attempt/storageNonce/workerNonce/boot的绑定；intent/created/result逐阶段持久ACK后才继续。心跳过期、业务终态、取消或发出SIGKILL都不能证明原worker已退出，不允许TTL抢占。
- 跨boot恢复须可信同一非克隆host的原token/MAC/稳定UUID、新boot_id与新认证checkin一致，不是硬件远程证明；无可靠DMI仅禁跨boot接管，不阻断普通同boot任务。storage-only禁止新磁盘许可与重复电源动作，仅原代际发布/回滚/清理，未知对象保留保护。
- NAS根预先存在，不自动chmod/chown；只读任务不建dev或写锁。单控制面单入口限制仍适用，不能识别全部DNS、物理目录或跨协议别名。本轮只交付源码和测试源码，真实权限、版本、恢复和三架构产物验证均待用户运行。
