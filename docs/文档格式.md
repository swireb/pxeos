## 文档排版规范

- 所有项目技术文档必须遵循本规范。
- 用户指定其他格式时以用户要求为准。

## 标题

- 所有标题统一使用 Markdown 二级标题。
- 不使用其他标题层级。
- 标题之间保留一个空行。
- 本规则适用于当前docs目录中的项目文档。

```text
## 标题名称
```

## 说明文字

- 标题下面的说明统一使用无序列表。
- 每项说明单独一行。
- 不使用有序列表或引用。

```text
- 第一项说明
- 第二项说明
```

## 代码块

- 命令、配置、脚本、路径、接口路径和参数必须放入代码块。
- 每个代码块必须声明语言类型。
- 按内容使用以下语言类型。

```text
shell
powershell
json
yaml
ini
xml
bat
text
```

## 代码注释

- 代码内部说明使用对应语言的注释。
- 多个对象放在同一代码块时使用注释区分。

```shell
#客户端
command-client

#服务端
command-server
```

## 配置文件

- 配置文件内容直接放入代码块。
- 不使用表格逐项解释。

```ini
PubkeyAuthentication=yes
PasswordAuthentication=no
```

## 参数列表

- 安装参数和启动参数统一写入一个文本代码块。
- 参数左对齐，说明写在同行注释中。

```text
/S                     #静默安装
/port=22               #监听端口
/password=<PASSWORD>   #密码占位符
```

## 文件路径

- 文件路径统一放入代码块。
- 多个路径使用注释区分。

```text
#客户端
C:\ProgramData\ssh\ssh_config

#服务端
C:\ProgramData\ssh\sshd_config
```

## 完整脚本

- 完整脚本保持在一个代码块中。
- 脚本内部允许空行区分逻辑。

```bat
@echo off

REM启动服务
net start sshd
```

## 示例命令

- 示例命令统一放入一个代码块。
- 每条命令占一行。

```shell
ssh Administrator@192.0.2.10 hostname
ssh Administrator@192.0.2.10 whoami
```

## 空行

- 标题、说明和代码块之间保留一个空行。
- 不连续插入多个空行。
- 文档结尾不保留多余空行。

## 内容顺序

- 每个模块依次写标题、说明、代码、补充说明、补充代码和测试结果。
- 没有代码或测试时省略对应部分。

## 禁止格式

- 禁止表格。
- 禁止引用。
- 禁止 Emoji。
- 禁止分割线。
- 禁止加粗和彩色文本。
- 禁止行内代码。
- 禁止无语言类型代码块。
- 禁止记录真实密码、Token、私钥和访问密钥。

## 文档维护

- 功能变化同步更新功能说明。
- 管理端 UI 页面规则只在 [前端UI规范](前端UI规范.md) 维护，其他文档仅提供入口链接，不复制现行规则。
- 开发和验收状态变化同步更新开发进度。
- 每次交付追加修改记录。
- 未修复风险保留在代码审查记录。
- 历史部署记录必须标明记录日期，不作为当前健康证明。
