## 故障处理

- Linux 后置安装失败先区分客户端能力、模式或散列拒绝、根发现与挂载、受管归属冲突、标签、事务恢复或清理待处理；失败不能当作正文执行成功。事务或目录含 foreign 项时保留证据，不手工递归删除或盲覆盖；固定路径与安全边界见 [RootPXE 集成](RootPXE集成.md)。
- 目标每次开机运行失败需检查受管单元加载属性和目标结果日志；平台没有虚构启动结果回传。journal 样本仅当前 invocation 最近 200 条且有字节上限，不能当作完整调试输出或秘密自动脱敏证明。

PXEOS 的错误处理使用 RootPXE token、MAC 与 `attention` 协议，不调用 FOG endpoint。默认凭据和日志脱敏要求见[安全配置](安全配置.md)，业务操作与 disk permit 前置条件见[RootPXE 集成](RootPXE集成.md)。

## Capture/restore 失败传播（2026-08-26）

本轮按 [e261c3b](https://github.com/FOGProject/fos/commit/e261c3b) 的问题模型和 [3b9eaff](https://github.com/FOGProject/fos/commit/3b9eaff) 的 `errexit` 重试保护人工适配。

- capture：`uploadFormat` 的压缩/分片后台流水线在独立 `pipefail` 子 shell 中运行；`savePartition` 与原始磁盘 capture 都在产物改名或完成前等待并检查对应 writer。partclone producer、压缩器、分片器或存储 writer 任一失败都会以 `capture` 阶段稳定错误码进入 attention，不能继续到 `imgcomplete` 成功回调。
- restore：镜像来源读取进程和解压/`partclone.restore` 流水线均被分别检查；split 镜像的 `img*` 只会展开为非空、可读的普通文件数组并保持 shell glob 顺序，无匹配或目录会在写盘前拒绝。任一非零退出分别以 `RESTORE_SOURCE_FAILED` 或 `RESTORE_PIPELINE_FAILED` 进入 attention，避免下游命令恰好返回 0 时掩盖错误。
- 完成通知：`pxeos.imgcomplete` 的 `finish` 回调以 `if` 包裹命令替换，因此即使运行器启用了 `bash -e`，短暂网络失败也会按既有退避重试；耗尽次数后以 `finish_notify` 阶段进入 attention，不会假报成功。

## 联调清单与边界

上述说明只覆盖受控 mock 回归，不能替代真实设备。必须在可牺牲设备上分别验证 NFS 与 SMB 的磁盘满、断链/权限拒绝、压缩器/partclone 故障、镜像读取故障，以及 `finish` 短暂不可达和最终不可达；日志与任务错误不得输出 token、SMB 密码或完整凭据。

还必须联调 GPT/MBR、512e/4Kn、NVMe、Windows unattend/无 unattend、失败 `attention` 和重试链路。内核、ARM64 与 Realtek 硬件验证边界见[硬件兼容性](硬件兼容性.md#构建与回退边界)；严禁在开发机系统盘验证。
