## 故障处理

- Linux Cloud-init 注入失败依据固定脱敏理由码定位，先检查客户端能力和私有正文校验，再检查镜像准备、目标根、磁盘许可、路径、缓存、seed 和文件读写。注入失败不代表用户配置已执行。
- SELinux 由目标系统或镜像准备负责关闭；现行 PXEOS 初始化不检测、修改或验证 SELinux 配置/状态和安全标签。旧标签错误码仅用于旧客户端与历史事件解释。
- 启用任务要求 v5 冻结模板能力及八个私有字符串。元数据支持固定实例标识与原生其他合法键，也可由显式宏生成随机实例标识；用户正文可空但仍携真实空字节散列，名称开关不会强制要求平台名称字段。网络或供应方配置为空时，对应正文与散列都为空。旧能力、旧自动元数据键、字段缺失、类型、字节上限或散列错误均拒绝，不自动转换。
- 用户与元数据始终存在，网络和供应方配置各非空时分别增加文件；种子必须恰好两个、三个或四个文件。清空配置不会删除目标已有的对应文件，已有额外文件、缺失或篡改均按外来种子处理。排查执行问题请核对目标首次开机的原生日志，不改 PXEOS 当前网络或 DHCP。
- 四份配置同等私密，元数据、供应方和网络配置也可能含凭据，不把正文粘贴到错误、任务日志、命令参数或共享诊断文档中。
- 未预装、明确禁用、缓存未清理、未知 seed、已有半份 seed 或内容不同应由镜像管理员核对并重新制作干净镜像；PXEOS 不清理未知目标内容。内容一致的 seed 只读接受不证明历史属于同一任务；实例标识不会替代镜像缓存清理。
- 目标开机执行问题由原生 Cloud-init 状态和日志定位；部署回执只有离线注入结果，不能替代目标首启验证。固定路径与安全边界见 [RootPXE 集成](RootPXE集成.md)。
- PXEOS 的错误处理使用 RootPXE 任务关联与 attention 协议，不调用 FOG endpoint。凭据与日志要求见 [安全配置](安全配置.md)。
- 首次任务失败即开始既有失败等待窗口。正常与 storage-only checkin 下发 `failureWaitSec`、`failureAction`；缺字段兼容 600 秒和重启。错误上报、存储恢复与回滚共享同一个起点，重试不会重新获得完整等待时间；首次已接受的错误响应可以更新策略，仍从原起点计算。
- 错误上报不可达或存储恢复持续被拒绝时，到期执行配置的重启或关机；永久拒绝的错误上报不会重复发送。未确认收尾时保留原执行的远端锁、占用与本地恢复证据，不把超时视为释放成功，也不接受新的写入执行。
- 只有错误上报已确认且存储安全停止、释放后，才提示并接受网页重试。storage-only 恢复成功不重复旧业务和完成电源动作；恢复失败到期仍执行失败电源动作。

```text
cloud_init_not_installed            #缺少可信配置或预装程序
cloud_init_explicitly_disabled      #禁用标志或原生服务被mask
cloud_init_cache_not_clean          #镜像含旧Cloud-init缓存
cloud_init_foreign_seed             #未知seed、额外文件、半份seed或内容不同
cloud_init_target_path_unsafe       #路径、属主、权限或链接不可信
cloud_init_seed_hash_mismatch       #原字节散列读回不匹配
cloud_init_label_tools_missing      #旧客户端/历史事件兼容；现行流程不触发
cloud_init_label_unverified         #旧客户端/历史事件兼容；现行流程不触发
cloud_init_seed_publish_failed      #本任务期望的两文件、三文件或四文件发布失败
cloud_init_seed_rollback_failed     #受控失败回滚未能证明完整清理
cloud_init_mount_cleanup_failed     #本次挂载或卷组清理失败
cloud_init_roots_not_unique         #没有唯一Linux根
cloud_init_disk_permit_invalid      #磁盘许可映射或硬件身份不匹配
```

## Linux 离线名称失败

- 先核对两个开关：只有 Cloud-init 关闭且计算机名称开启才离线写配置，不需要 Cloud-init 包，也不检查或清理缓存、seed。Cloud-init 开启时名称配置由服务端渲染任务副本，PXEOS 不离线改名。
- 离线名称要求当前客户端声明独立能力；管理名称必须为有效单标签，冻结策略名称必须与任务名称一致。多根、许可缺失、未授权物理卷及不支持的配置目录挂载都拒绝，不猜首盘。
- 路径、属主、模式、链接、回读和清理失败不会上报成功。受控回滚不能确认归属时保留原文件替换及事务备份，下一次预检明确拒绝；管理员先核对证据，不盲删或覆盖。多文件更新不承诺掉电原子性。
- 模板启用时只报告 Cloud-init 或 Windows 应答文件注入成功，名称回执为 false；独立离线名称回执只证明文件更新和清理成功。模板固定名称保留，不因管理端名称不同而在 PXEOS 中覆盖，两类回执均不能替代客户机启动验证。

```text
linux-hostname-offline-v1                      #独立能力
linux_hostname_invalid                        #管理名称非法
linux_hostname_policy_invalid                 #冻结任务策略缺失或管理名称不一致
linux_hostname_unique_permitted_root_required  #完整许可集合内没有唯一可信根
linux_hostname_path_unsafe                     #配置路径、链接或元数据危险
linux_hostname_unsupported_mount               #配置目录或文件被额外挂载
linux_hostname_label_tools_missing             #旧客户端/历史事件兼容；现行流程不触发
linux_hostname_label_unverified                #旧客户端/历史事件兼容；现行流程不触发
linux_hostname_preflight_or_path_rejected      #写阶段重新预检或路径检查拒绝
linux_hostname_readback_failed                 #原文字节或文件元数据读回失败
linux_hostname_write_failed                    #受控文件写入失败
linux_hostname_rollback_failed                 #不能证明已恢复本次修改
linux_hostname_cleanup_failed                  #暂存或备份清理失败
linux_hostname_mount_cleanup_failed            #本次挂载或卷组清理失败
linux_hostname_transaction_evidence_present    #发现未证明清理的旧事务证据
```

## Capture/restore 失败传播（2026-08-26）

- 历史说明按 [e261c3b](https://github.com/FOGProject/fos/commit/e261c3b) 的问题模型和 [3b9eaff](https://github.com/FOGProject/fos/commit/3b9eaff) 的失败重试保护人工适配。
- 捕获的压缩与分片后台流水线独立检查失败；产物改名或任务完成前等待对应写入进程。Partclone、压缩器、分片器或存储写入任一失败都进入 attention，不能继续成功回调。
- 还原分别检查镜像读取进程和解压、Partclone 流水线。分片只接受非空、可读的普通文件并保持既有顺序，无匹配或目录在写盘前拒绝；下游命令成功不能掩盖来源失败。
- 完成回调保留失败重试保护，短暂网络失败按既有退避重试；耗尽次数后进入 attention，不会假报成功。

```text
capture                  #捕获流水线失败阶段
RESTORE_SOURCE_FAILED    #镜像来源读取失败
RESTORE_PIPELINE_FAILED  #解压或还原流水线失败
finish_notify            #完成通知重试耗尽阶段
```

## 存储 409 诊断

捕获准备、预检或安全收尾失败时，查看 `/tmp/log/pxeos-task.log` 中的 `endpoint`、HTTP 状态、`reasonCode`、受控中文错误，以及检查点的 `sequence`、`phase`、`operation`。服务端同一请求的结构化日志还包含任务编号、执行轮次和路径角色；节点身份不符时记录经过校验的预期/实际 FileID，不记录原始路径、owner 内容或凭据。管理端重试日志以 `endpoint=task_retry` 区分内核下载准入、存储待收尾及其他拒绝阶段；409 本身不能证明是哪一类。

## 联调清单与边界

- 上述说明只覆盖受控 mock 回归，不能替代真实设备。必须在可牺牲设备上分别验证 NFS 与 SMB 的磁盘满、断链/权限拒绝、压缩器/Partclone 故障、镜像读取故障，以及完成通知短暂不可达和最终不可达；日志与任务错误不得输出令牌、SMB 密码或完整凭据。
- 还必须联调 GPT/MBR、512e/4Kn、NVMe、Windows 有无应答文件、失败 attention 和重试链路。内核、ARM64 与 Realtek 硬件验证边界见 [硬件兼容性](硬件兼容性.md#构建与回退边界)；严禁在开发机系统盘验证。
